# 文献检索来源接入调研

日期：2026-11-01

当前实施选择：知网与 Google Scholar 均先用本地模拟数据完成页面及交互。真实来源的接入方案保留在本文，后续切换时仍需按来源分别验证。

## 结论

| 来源 | 可确认的接入方式 | 当前可稳定自动化程度 | 对本项目的建议 |
| --- | --- | --- | --- |
| Google Scholar | 官方提供网页检索和单篇引文导出，但明确不提供批量记录访问；第三方 SerpApi 提供结构化 Scholar 检索结果接口 | 使用 SerpApi Key 可以自动获取结果元数据，但这不是 Google 官方 API | 自动检索需用户接受第三方服务，并在 `.env` 中配置其 Key；否则采用人工导入 BibTeX/RIS |
| 中国知网 CNKI | 官方网页检索；目前未检索到可直接申请的公开文献检索开发者接口文档 | 无授权接口前，不应把网页爬取当作稳定产品能力 | 有机构或商务授权接口时按文档接入；此前采用用户手动导出/导入元数据与自有合法 PDF |

Google Scholar 官方帮助说明：结果通常按相关度排序、全文可能需要订阅、支持单篇 BibTeX 等引文导出，同时要求自动访问遵守 robots.txt，并明确不提供批量记录访问。来源：[Google Scholar Search Help](https://scholar.google.com/intl/en/scholar/help.html)。

知网会员协议明确对异常下载设置限制，并把以机器人、蜘蛛或爬虫程序下载文章列为违约行为。此处讨论的是会员文章下载；它不等于对所有网页元数据访问作出统一结论，但足以说明不能把批量全文抓取作为默认实现。来源：[中国知网会员服务使用协议](https://wap.oversea.cnki.net/cn/member/agreement.html)。

SerpApi 的 Google Scholar 接口支持查询词、出版年份上下限、偏移量和每页 1–20 条结果，返回标题、链接、检索片段、出版信息及部分 PDF 资源链接。它是第三方抓取服务，数据质量和可用性依赖服务商，且需要单独的 API Key。来源：[SerpApi Google Scholar API](https://serpapi.com/google-scholar-api)、[SerpApi pricing](https://serpapi.com/pricing)。

## 建议的数据路径

1. 表单输入主题、年份范围、每源抓取数量和排序方式。
2. 每个来源由独立适配器执行；记录原始来源、检索时间、原文链接、是否有摘要、是否有可访问 PDF。某个来源失败时显示该来源失败原因，不伪造或混标另一来源结果。
3. 用 DOI 优先、规范化标题加年份兜底进行去重。对无 DOI 的匹配给出较低置信度，不自动合并明显不同版本。
4. 初始排序保留来源相关度，再按用户选项重新排序。请求 20 篇应表示最多返回 20 篇去重后的结果；不足时显示真实数量。
5. AI 分析采用证据等级：只有题录/片段时仅显示题录和片段；有完整摘要时可生成摘要级概述、研究目的和摘要中明确的方法；有可读取全文时才分析实证过程。每个字段保存依据类型与来源片段；信息不足时明确标注“原文未提供，无法判断”。
6. 原文与 PDF 下载分别链接到出版商或开放获取资源；不假定所有结果存在可下载 PDF。Zotero 导入可使用用户明确选择的题录，后续单独接入本地 Zotero。

Zotero Desktop 的本地 API 位于 `localhost:23119/api/`。写入需要由用户在 Zotero 中授权的本地 API Key，适合后续实现原型里的“导入 Zotero”；不能直接写入其内部 SQLite 数据库。来源：[Zotero Local API](https://www.zotero.org/support/dev/web_api/v3/local_api)。

## 待确定的产品选择

- Google Scholar 是否采用 SerpApi，还是优先支持人工导入。
- 是否已有 CNKI 授权检索接口文档。
- 缺少全文时，是否允许显示带证据等级的摘要级分析。

无论选择哪条路径，结果页都应让用户看清“实际来源”和“分析依据”，避免把检索片段误称为论文摘要或全文分析。
