# 个人论文助手｜落地版 PRD

## 一、概述

**文档信息**

| 版本号 | 日期 | 作者 | 文档范围 |
| --- | --- | --- | --- |
| V1.1.1 | 2026-11-03 | Chelsea | 补充已开发的会话附件检索问答能力，明确其与个人文献库 RAG 的实施边界 |

**实施状态说明：**文献检索、精读、文献库、AI 对话（包含当前会话上传附件的关键词检索辅助回答）、任务记录、设置及 Zotero 集成已有可运行实现。当前对话尚未检索整个个人文献库；“个人文献库 RAG 问答”和“检索结果逐篇并发 AI 分析”是本 PRD 的**新增开发需求**。本文的验收标准是目标行为，不代表现状已达成。

### 1. 需求背景

- **目标用户现状：**写毕业论文的本科生与持续阅读文献的硕士、博士生，在论文期间可能每天检索、阅读与整理资料。典型工作流是从知网或 Google Scholar 检索、下载 PDF、手动做笔记、再用 Zotero 管理。
- **核心痛点：**文献、PDF、笔记与阅读报告散落在不同工具中；积累后难以快速找回证据，普通 AI 对话也无法直接利用个人长期保存的文献库。

| 问题点 | 问题描述 | 当前影响 |
| --- | --- | --- |
| 检索与精读割裂 | 候选论文需手动复制 DOI、下载和整理 | 一篇论文从发现到产出报告的步骤多，易丢失来源 |
| 阅读成果分散 | 原文、中文翻译、模板报告及主题分类分别保存 | 难以持续复用和追溯研究依据 |
| AI 缺少个人语境 | 当前对话仅能搜索当次会话附件，不能召回完整文献库 | 跨论文比较和后续提问需反复上传材料 |
| 检索结果分析负担高 | 当前页面只有元数据及摘要，方法/实证字段常因证据不足留空 | 用户仍需逐条筛选，并判断哪些值得精读 |

### 2. 需求目标

- **业务目标：**让用户在同一产品内完成“检索→筛选→精读→入库→基于库问答”，持续积累个人研究资产。
- **业务目标：**用可靠的证据边界提供逐篇 AI 分析和带来源引用的问答，减少重复查找与整理。
- **业务目标：**验证学生在写论文阶段是否会持续使用检索、精读与文献库，而非只体验一次 AI 功能。

| 指标 | 当前状态 | 目标状态 |
| --- | --- | --- |
| 周持续使用 | 未建立正式试用样本与埋点 | 建议默认值：邀请至少 10 名目标学生连续试用 2 周，第二周仍使用核心功能的比例 ≥40% |
| 检索任务完成 | 已有检索任务记录，未汇总漏斗 | 建议默认值：成功返回至少 1 篇结果的检索占有效提交的 ≥90%；按外部 API 故障单独分组 |
| 精读任务完成 | 已有状态记录，未汇总完成率 | 建议默认值：取得可提取文字 PDF 的任务中，最终生成报告的比例 ≥80% |
| 文献库复用 | 现有文献库无召回使用统计 | 建议默认值：试用用户中 ≥50% 在一周内再次打开已入库文献或发起带引用的文献库问答 |
| AI 证据质量 | RAG 与逐篇分析尚未实现 | 建议默认值：人工抽查 50 条 AI 结论，引用可定位率 ≥90%，无证据却写成确定结论的比例 ≤5% |

指标均为**建议验收目标而非项目已有成绩**。本地版仅记录匿名本机事件与任务状态；试用统计由参与者自愿导出汇总，不上传论文全文或提问内容。

### 3. 需求范围

- **包含（P0）：**中英文文献检索与结果快照；检索结果逐篇受控并发 AI 分析；DOI/链接/PDF 精读及按个人模板生成中文报告；主题/精读文献库；基于整个个人文献库的 RAG 问答与来源引用。
- **包含（P1）：**首页与任务记录、导入 Zotero、个人偏好与报告模板设置、失败重试和结果下载。
- **不包含：**在线多用户账号、学校组织权限、个人订阅收费、知网正式自动抓取、扫描 PDF OCR、对付费墙内容的绕过、跨用户共享文献库、移动端原生应用。
- **产品形态：**本版仍以本地单用户 Web 应用验收；未来在线多用户是后续独立版本。新增 RAG 的数据结构应预留用户归属字段，但本版不宣称已实现多用户隔离。
- **商业模式：**本版免费用于需求验证；未来在线版本面向学生个人收费，定价和支付不属于本版范围。

### 5. 用户、场景与权限

**目标用户与场景**

| 用户群 | 使用阶段与频率 | 触发场景 | 目标与完成标志 |
| --- | --- | --- | --- |
| 本科毕业论文学生 | 开题至写作期，预计几乎每天使用 | 对课题不了解，需要快速找到候选论文 | 检索并筛出可读论文；按学校/导师模板完成至少一篇阅读报告 |
| 硕士、博士生 | 选题、文献综述、研究设计阶段，预计高频使用 | 持续追踪同一主题，比较多篇论文的方法与结论 | 文献按主题积累，能从个人库检索到可核对的原文证据 |
| 两类用户的共同场景 | 写作或讨论期间随时发生 | 想追问“我收藏的论文如何解释某问题” | AI 回答引用本人已入库文献；无法引用时明确说明材料不足 |

**角色定义与部署边界：**本版是本机单用户产品，只有一个“本地资料拥有者”，不提供注册、登录、共享或真正的多角色 RBAC。后台任务执行器是服务内部身份，不是可登录角色；远程访问者不是允许的产品用户。**当前代码没有应用层鉴权**，因此部署必须绑定 `127.0.0.1`，不得将端口转发到公网或供同机不可信用户共用。本版验收权限靠“本机访问边界 + 服务端数据归属校验设计”；未来在线版另行设计学生账号、运营管理员和组织权限，不能把预留字段当成已完成的权限能力。

**本版权限矩阵**（“内部”表示只能由服务端处理流程调用，不能由浏览器传参冒充）：

| 操作 | 本地资料拥有者 | 服务内部任务执行器 | 远程/未授权访问者 | 约束 |
| --- | --- | --- | --- | --- |
| 查看检索结果、文献库、对话与任务 | 允许 | 为处理任务按需读取 | 不允许 | 仅本机访问；未来按 `user_id` 隔离 |
| 创建检索、精读、RAG 问答任务 | 允许 | 不主动创建用户任务 | 不允许 | 后端校验输入和对象归属，不能只依赖前端按钮 |
| 上传/下载/删除本人文献与模板 | 允许 | 只处理任务所需文件 | 不允许 | 文件访问需通过服务端 ID 查询与权限判断 |
| 写入分析、翻译、索引与报告结果 | 不可直接写内部结果字段 | 内部允许 | 不允许 | 状态转换和结果写入仅服务端完成 |
| 管理模型/检索 API Key | 通过本地 `.env` 配置 | 读取最小必需密钥 | 不允许 | 密钥不返回前端、不进入日志 |
| 授权 Zotero 并导入 | 本机用户在桌面端授权后允许 | 按授权执行导入 | 不允许 | 授权由 Zotero Desktop 完成；断开后不可写入 |
| 查看其他用户资料/管理他人账号 | 不适用 | 不适用 | 不允许 | 多用户功能不在本版范围 |

**权限兜底：**任何请求若引用不存在、未归属当前本地资料库、已删除或未完成的对象，服务端返回 404/409，不泄露文件内容；后台任务只能使用其任务记录绑定的文献和模板。建议默认值：新增 RAG 的切片和分析结果记录预留 `owner_id`，本地版统一写固定本机所有者 ID；在线版上线前必须补完整身份认证与跨用户隔离测试。

## 四、功能说明

### 功能 1：中英文文献检索与逐篇 AI 分析（P0）

**功能描述**

用户在文献检索页输入研究主题、语言、年份、数量与排序，立即获得元数据列表；每篇的 AI 分析随后独立更新。分析字段为简要摘要、研究目的、研究方法、实证过程，必须标注依据是检索摘要还是全文。建议默认值：本版批量分析只使用检索元数据与摘要/片段，**不自动下载每条结果的全文 PDF**；无法证实的字段填写“摘要未提供，需阅读全文”，单篇精读完成后可产生全文级分析。

**用户流程**

```text
首页快捷入口/左侧“文献检索” → 输入条件 → 开始检索
  ├─ OpenAlex 成功 → 即时显示元数据；不足时 SerpApi 补充
  ├─ OpenAlex 失败且 SerpApi 成功 → 显示兜底结果与来源说明
  ├─ 两源均失败 → 保留上次结果，提示重试，不生成空任务
  └─ 零结果 → 提示缩短关键词或扩大年份
结果入库并保存快照 → 每篇进入 AI 分析队列（建议默认并发 3）
  ├─ 有证据 → 逐条显示四项分析及证据级别
  ├─ 证据不足 → 对相应字段显示“需阅读全文”
  └─ 单篇调用失败/超时 → 该篇可重试，其他篇不受影响
用户可翻页、勾选导入文献库/Zotero，或选一篇创建精读任务
```

**状态机**

| 对象/状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 检索未开始 | 无历史快照 | 用户提交 | 输入引导；有历史时恢复最近一次结果 |
| 检索中 | 表单通过校验 | 成功/失败/零结果 | 按钮禁用、“检索中” |
| 检索已完成 | 至少一个源返回 | 用户重检索 | 列表、来源、数量与分页；结果快照保存 |
| 检索失败/无结果 | 全部源失败或返回零条 | 修改条件并重试 | 错误或空状态，不清空已有快照 |
| 单篇待分析 | 元数据已保存 | 工作者领取 | “AI 分析待开始” |
| 单篇分析中 | 工作者领取 | 成功/证据不足/失败 | 单篇骨架屏，不阻塞列表 |
| 单篇已分析/证据不足 | 结构化结果校验通过 | 内容版本变化 | 展示四字段与依据；缺失字段明确标记 |
| 单篇分析失败 | 调用或校验失败 | 用户重试 | 错误提示和“重试分析” |

**字段规范**

| 字段 | 类型 | 必填 | 限制 | 校验与错误提示 |
| --- | --- | --- | --- | --- |
| 研究主题/关键词 | 文本 | 是 | 2–200 字符 | 去首尾空格；不足 2 字：“请至少输入 2 个字符” |
| 文献类型 | 单选 | 是 | 中文/英文 | 无选择：“请选择中文或英文文献” |
| 发表时间 | 起止年份 | 是 | 1900–2100；界面建议 2015–当年 | 起始晚于结束：“起始年份不能晚于结束年份” |
| 抓取数量 | 单选 | 是 | 10/20/30/50/100 篇 | 超出 1–100：拒绝请求 |
| 排序 | 单选 | 是 | 相关度/年份升序/年份降序 | 非法值：“无效的排序方式” |
| 分析输出 | 结构化对象 | 系统生成 | 四字段、依据文本、依据级别、状态 | 不接受模型没有证据支撑的确定结论；缺失字段置“需阅读全文” |

**文案规范**

| 场景 | 文案 |
| --- | --- |
| 空状态 | “输入主题并开始检索”；零结果：“没有找到匹配文献，请调整关键词或年份。” |
| 加载中 | “正在检索文献…”；单篇：“正在分析这篇文献…” |
| 操作成功 | “找到 {n} 篇文献，AI 分析将逐条更新。” |
| 操作失败 | “检索失败，已保留上次结果。”；“这篇文献分析失败，可单独重试。” |
| 权限不足 | “当前无法访问该文献或 PDF，请查看来源页面。” |
| 网络异常 | “网络连接中断，请检查网络后重试；已保存的结果仍可查看。” |

**异常情况处理**

| 场景 | 触发条件 | 处理方式 | 用户反馈 |
| --- | --- | --- | --- |
| OpenAlex 不可用 | 请求错误/限流 | 用 SerpApi 兜底；记录来源 | “OpenAlex 暂不可用，已使用补充检索源。” |
| SerpApi 不可用 | 密钥缺失、额度或请求失败 | 有 OpenAlex 结果则保留部分结果；无结果则失败 | “补充检索不可用，当前展示 {n} 篇。” |
| AI 超时 | 建议默认值：单篇 60 秒 | 建议默认值：退避重试 2 次，仍失败则该篇失败 | “单篇分析超时，可重试。” |
| AI 返回无法校验的内容 | 非结构化、字段缺失或引用无依据 | 不写入确定结论；重试或标注证据不足 | “分析依据不足，请阅读全文。” |
| 用户刷新/离开页面 | 仍有分析任务 | 状态与结果落库，返回时恢复 | “分析仍在进行，可稍后回来查看。” |
| 文献元数据重复 | DOI/来源记录重复 | 按来源 ID 与 DOI 去重并复用缓存 | 不重复展示与计费 |

**验收标准：**建议默认值：同一任务最多 3 篇同时调用 AI；列表首批返回不等待全部 AI 分析；单篇失败不影响其他篇；刷新后分析状态与结果可恢复；每个输出字段能看到依据级别，缺证据时不编造。

### 功能 2：文献精读、翻译与模板阅读报告（P0）

**功能描述**

用户从检索结果选一篇，或在精读页输入 DOI/链接、上传 PDF，获得可下载的原文、英文论文中文版 PDF、按个人模板填写的中文阅读报告。报告模板是任务创建前的必备条件，任务保存当时的模板副本。

**用户流程**

```text
检索结果单选“精读文献”/精读页输入 DOI、链接或 PDF
  ├─ 未上传模板 → 引导“设置 > 文献工具”上传模板，暂不创建任务
  ├─ 输入或文件无效 → 就地提示修改
  └─ 创建任务 → 排队 → 获取 PDF（DOI: OpenAlex 优先，SerpApi 兜底）
       ├─ 无合法可下载 PDF → 失败并建议手动上传
       └─ 获取成功 → 提取全文；失败/扫描件 → 提示需可提取文字 PDF
            → 判断语言 → 英文逐段翻译并保存进度；中文跳过
            → 报告 Agent 顺序阅读、压缩记忆、按模板填中文内容
            ├─ 模型/渲染失败 → 保留原文与可用中间结果、支持重试
            └─ 完成 → 显示和下载成果，自动更新精读文献库
```

**状态机**

| 状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 待创建 | 尚未提交 | 提交成功 | DOI/链接与上传两种入口 |
| 排队中 | 任务写入数据库 | 工作者领取 | “任务正在排队” |
| 获取中 | 工作者领取 | 获得 PDF/失败 | “正在获取原文 PDF” |
| 提取中 | PDF 获得 | 文本有效/失败 | “正在提取全文” |
| 翻译中 | 判定英文 | 翻译完成/失败 | 已完成段落数/总段落数 |
| 报告中 | 中文跳过翻译或英文翻译完成 | 完成/失败 | “正在生成阅读报告” |
| 已完成 | 原文与报告生成 | 用户下载或重新创建 | 三标签结果与下载按钮；中文论文不显示翻译标签 |
| 失败 | 任一阶段不可恢复错误 | 用户重试 | 失败阶段、错误原因、重试按钮 |

**字段规范**

| 字段 | 类型 | 必填 | 限制 | 校验与错误提示 |
| --- | --- | --- | --- | --- |
| DOI/链接 | 文本 | 与 PDF 二选一 | ≤2000 字符 | DOI 格式或公开 HTTPS 的 DOI/arXiv/PDF 链接；否则“请输入有效 DOI 或 HTTPS 论文链接” |
| 上传文件 | PDF | 与 DOI/链接二选一 | 建议默认值：≤10 MB | 扩展名、PDF 文件头和可读取性校验；不合格提示原因 |
| 阅读报告模板 | MD/PDF/DOCX/XLSX | 是，先在设置上传 | ≤5 MB；只保存一份 | 必须能提取文字/栏目；缺失：“请先上传文献阅读报告模板” |
| 报告语言 | 固定值 | 是 | 中文 | 本版不可改为英文 |

**文案规范**

| 场景 | 文案 |
| --- | --- |
| 空状态 | “输入 DOI、论文链接或上传 PDF，开始精读。” |
| 加载中 | “正在逐段翻译（{done}/{total}）”；“正在阅读原文并生成报告…” |
| 操作成功 | “精读已完成，原文与阅读报告已保存至精读文献库。” |
| 操作失败 | “精读失败：{可读原因}。可重试或上传原文 PDF。” |
| 权限不足 | “无法取得该论文的公开全文，请上传你有权使用的 PDF。” |
| 网络异常 | “下载或模型连接中断，进度已保存，请稍后重试。” |

**异常情况处理**

| 场景 | 触发条件 | 处理方式 | 用户反馈 |
| --- | --- | --- | --- |
| DOI 无开放获取全文 | OpenAlex/SerpApi 未取得可验证 PDF | 任务失败，不推断全文 | 引导手动上传 PDF |
| 扫描件/加密/超限 | 无足够可提取文字、加密、超过 300 页或 100 万字符 | 停止处理，原文可保留 | “需未加密且可提取文字的 PDF” |
| 翻译单段失败 | 模型报错或空输出 | 保存已完成段落，支持重试 | 显示失败段落进度 |
| 报告失败 | 模型/模板渲染错误 | 保留原文和翻译；重试报告流程 | “报告生成失败，可重试” |
| 页面关闭/服务重启 | 后台任务未完成 | DB 记录状态；重启恢复排队任务 | 返回页面继续查看状态 |

### 功能 3：个人文献库整理与索引同步（P0）

**功能描述**

用户将检索结果归入主题，精读原文和报告自动进入精读文献库，也可手动上传论文。文献库是 RAG 的唯一受控知识来源；只有取得且能提取文字的内容才标为“可用于 AI 问答”。

**用户流程**

```text
检索结果勾选 → “导入文献库” → 选择已有主题/新建主题
  ├─ 主题无效或条目重复 → 提示原因或已存在数量
  └─ 导入成功 → 文献库主题列表可见元数据
精读获取原文 → 自动保存至精读文献库 → 翻译/报告完成后补齐文件
本地上传 → 填写元数据、选库/主题、提交 PDF
  ├─ PDF 无文字/损坏 → 可保留合法文献元数据与原文；索引标为失败并引导上传可提取版本
  └─ 有可提取文字 → 创建/更新文献切片与向量索引 → 可供 RAG 检索
用户查看、筛选、下载或删除文献 → 索引同步更新
```

**状态机**

| 状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 库为空 | 无真实文献 | 导入/上传/精读归档 | 引导检索或上传 |
| 只有元数据 | 从检索导入但无 PDF | 补上传/精读取回 PDF | 标“尚无全文”，不参与全文 RAG |
| 索引待建/建立中 | 原文新增或更新 | 成功/失败 | 文献可查看，AI 问答暂不使用 |
| 已索引 | 切片和向量写入成功 | 原文变更/删除 | 标“可用于 AI 问答” |
| 索引失败 | PDF 不可提取或向量服务失败 | 重建成功 | 文献仍可查看，提供重试入口 |
| 已删除 | 用户确认删除 | 无 | 从列表及索引消失；关联精读任务按现有数据关系处理 |

**字段规范**

| 字段 | 类型 | 必填 | 限制 | 校验与错误提示 |
| --- | --- | --- | --- | --- |
| 主题名称 | 文本 | 新建主题时是 | 1–100 字符 | 去空格、同名拒绝；“该主题已经存在” |
| 论文标题 | 文本 | 手动上传时是 | 1–500 字符 | 为空：“请输入论文标题” |
| 作者 | 文本 | 否 | ≤500 字符 | 超限：“作者信息过长” |
| 摘要 | 文本 | 否 | ≤5000 字符 | 超限：“摘要不能超过 5000 字符” |
| DOI | 文本 | 否 | 标准 DOI 格式 | 错误：“DOI 格式不正确” |
| 来源链接 | URL | 否 | HTTPS、≤2000 字符 | 错误：“来源链接需使用 HTTPS” |
| 原文 PDF | 文件 | 手动上传时是 | 建议默认值：≤10 MB | 必须为有效 PDF；否则说明原因 |
| 中文 PDF | 文件 | 否 | 建议默认值：≤10 MB | 必须为有效 PDF |

**文案规范**

| 场景 | 文案 |
| --- | --- |
| 空状态 | “文献库还没有论文。可从检索结果导入，或上传本地 PDF。” |
| 加载中 | “正在保存文献…”；“正在为这篇论文建立问答索引…” |
| 操作成功 | “已导入 {n} 篇至「{主题}」；{m} 篇已存在。” |
| 操作失败 | “文献保存失败，请重试；已上传的文件不会标为可检索。” |
| 权限不足 | “该 PDF 无法访问，请上传你有权使用的文件。” |
| 网络异常 | “连接中断，当前文献仍保留；索引可稍后重建。” |

**异常情况处理**

| 场景 | 触发条件 | 处理方式 | 用户反馈 |
| --- | --- | --- | --- |
| 重复导入 | 来源记录 ID 已入库 | 不重复插入；允许按现有规则调整主题 | 显示新增与已存在数量 |
| 检索结果无原文 | 只有 DOI/摘要/链接 | 保存元数据；标“只有元数据” | 不将摘要误称为全文 |
| 索引服务失败 | 切片/Embedding/向量写入失败 | 保留文献记录，记录错误，支持重建 | “文献已保存，AI 问答索引尚未建立” |
| 文件更新或删除 | 原文版本变化或用户删除 | 旧切片与旧向量失效，同步重建/清理 | 更新索引状态 |
| 数据库不可用 | 写入失败 | 事务回滚，不显示成功 | “文献库暂不可用” |

**验收标准：**三类列表可区分；检索导入与精读自动归档可追溯来源；元数据和文件不混淆；新增/更新/删除原文会同步影响 RAG 可检索范围，索引失败不丢文献记录。

### 功能 4：基于整个个人文献库的 RAG 问答（P0）

**功能描述**

**现有能力与新增范围：**当前 AI 对话已支持上传附件，并提供在**当前会话附件文本中按关键词查找原文片段**的 Agent 工具。这是已开发的检索辅助问答能力。它不读取文献库中的其他论文，也未实现文献切片、Embedding、向量召回及库内引用定位。以下流程、字段和验收标准描述的是待开发的**整个个人文献库 RAG**。

用户在 AI 对话页选择“基于文献库回答”（建议默认开启），对已索引的个人论文提问。系统检索相关片段后再调用模型，回答必须展示可点击的文献标题及页码/章节来源；没有证据时明确拒绝把通用知识包装为库内结论。普通对话与本次会话附件问答继续保留。

**用户流程**

```text
文献库已有可索引论文 → 解析/切片/Embedding → 建立个人库索引
AI 对话输入问题并选择“基于文献库回答”
  ├─ 库为空/均未索引 → 引导导入文献或修复索引，不伪造引用
  └─ 根据问题召回并重排相关片段 → 将片段、来源和对话上下文送入 Agent
       ├─ 证据充分 → 回答关键结论并附文献、页码和原文片段入口
       ├─ 证据不足/矛盾 → 说明无法确定，列出可核实来源
       └─ 检索/模型失败 → 保留用户问题，允许重试
用户点击引用 → 文献库定位原文；继续追问沿用当前会话上下文
```

**建议默认检索策略：**按段落/标题和页码切片，每片约 800 个中文字符、相邻片重叠 120 字；关键词和向量混合召回后去重，最多送入 6 个片段。Embedding 模型和向量索引实现需支持版本号、文本哈希、文献 ID 与失效重建；建议默认在本地保存索引，MySQL 保存切片元数据。上述数值为初始实施参数，需通过有标注的问题集评估后调优。当前单用户版本使用本地库范围；未来在线版必须加入账户认证和用户级隔离，本版不提供多用户能力。

**状态机**

| 状态 | 进入条件 | 退出条件 | 用户可见表现 |
| --- | --- | --- | --- |
| 未就绪 | 库为空或无已索引全文 | 文献索引成功 | “文献库暂无可用于问答的原文” |
| 待提问 | 索引可用 | 提交问题 | 输入框与模式开关 |
| 召回中 | 问题提交 | 获得片段/失败 | “正在检索你的文献库…” |
| 生成中 | 有召回片段 | 模型返回/失败 | “正在依据文献生成回答…” |
| 有依据回答 | 模型返回且引用校验通过 | 下次提问 | 答案和来源卡片 |
| 证据不足 | 召回为空或引用不支持结论 | 用户补充文献/改问 | “个人文献库中没有足够依据” |
| 失败 | 索引/模型/网络错误 | 重试成功 | 保留问题并提供重试 |

**字段规范**

| 字段 | 类型 | 必填 | 限制 | 校验与错误提示 |
| --- | --- | --- | --- | --- |
| 问题 | 文本 | 是 | ≤12000 字符 | 空问题且无附件：“请输入问题或添加附件” |
| 问答模式 | 单选/开关 | 是 | 文献库问答/普通对话 | 默认文献库问答；切换不删除历史 |
| 会话附件 | 文件 | 否 | 最多 8 个，单个建议默认 ≤10 MB | PDF、DOCX、TXT、PNG、JPG、WEBP；不合格提示格式/大小 |
| 引用记录 | 系统生成 | 文献库问答时是 | 文献 ID、切片 ID、页码/章节、证据文本 | 必须属于当前文献库且能定位，不接受模型自造引用 |

**文案规范**

| 场景 | 文案 |
| --- | --- |
| 空状态 | “先导入或精读论文，就能基于个人文献库提问。” |
| 加载中 | “正在检索你的文献库并核对出处…” |
| 操作成功 | “已依据 {n} 篇文献回答，点击引用可查看原文。” |
| 操作失败 | “本次回答失败，你的问题已保存，可重试。” |
| 权限不足 | “这篇文献不在当前个人文献库中，无法作为回答依据。” |
| 网络异常 | “模型连接中断；已保存的问题和文献不会丢失。” |

**异常情况处理**

| 场景 | 触发条件 | 处理方式 | 用户反馈 |
| --- | --- | --- | --- |
| 库为空/无全文 | 无已索引切片 | 不调用模型生成“库内回答” | 引导导入或上传可提取文字 PDF |
| 召回为空 | 相似度/关键词均无可靠命中 | 明确证据不足，可展示相关文献供手动查看 | “个人文献库中没有足够材料回答” |
| 引用越界/幻觉 | 模型引用不存在的文献、页码或片段 | 服务端校验后拒绝该引用，必要时要求模型重写 | 不展示未经验证的引用 |
| 索引版本落后 | 文献原文更换后索引未完成 | 暂停该文献召回，后台重建 | “部分文献正在更新索引” |
| 模型超时 | 建议默认值：120 秒 | 保存问题，展示重试 | “回答超时，请重试” |
| 多用户风险 | 未来在线版未完成身份隔离 | 不开放在线多用户 | 本版仅单用户本地使用 |

**验收标准：**入库原文更新后可重建索引；文献库问答不使用未入库文件冒充证据；引用可回到正确文献及页码/章节；无证据时明确说明；原有普通对话及当前会话附件能力仍可用。

### 2. 超时、失败与异常降级

下表的“现有”数值来自当前代码；“建议默认值”是本版新增能力的验收目标。超时是单次调用上限，不等于外部服务可用性承诺。

| 依赖/动作 | 超时与重试 | 失败时的降级和用户反馈 | 结果保留规则 |
| --- | --- | --- | --- |
| OpenAlex 查询 | 现有：连接 8 秒、总计 25 秒 | 切换 SerpApi；提示“正在使用备用检索源” | 已取得的有效结果继续保留并标注来源 |
| SerpApi 查询 | 现有：连接 8 秒、总计 35 秒 | 若已有 OpenAlex 结果则展示部分结果；两者均失败则任务失败并提供重试 | 不用模拟数据冒充真实检索结果；历史成功任务不被覆盖 |
| PDF 下载 | 建议默认值：单文件 30 秒、10 MB 上限；瞬时错误最多重试 1 次 | 显示“无法获取原文，请上传 PDF”；保留元数据与检索结果 | 不把 HTML/错误页保存成 PDF，不生成虚假的精读结果 |
| DeepSeek 精读调用 | 现有：单次 120 秒、最多 2 次重试 | 精读任务记失败原因并允许重试；已保存原文继续保留 | 不把缺页或未完成翻译标成“已完成” |
| DeepSeek 逐篇分析/RAG | 建议默认值：单次 120 秒、最多 2 次重试；逐篇任务独立失败 | 单篇显示“分析失败/重试”；RAG 退回到“检索证据不足”或提示模型暂不可用 | 其他文献分析与检索结果不受影响；不使用无证据的模型回答冒充个人库结论 |
| Zotero 本机接口 | 现有：普通请求 15 秒、写入 30 秒、附件 60 秒、授权等待 120 秒 | 标记 Zotero 导入失败并给出“检查客户端/授权后重试” | 本产品文献库和精读结果不回滚；重试时按来源 ID 去重 |
| MySQL 读写 | 建议默认值：连接 3 秒；请求超时由接口层统一控制 | 返回可识别的 503/任务失败，不展示“已保存” | 事务回滚；后台任务在恢复后按持久化状态继续或重试 |

接口返回需包含可追踪的错误码和请求 ID，页面展示可执行的下一步。密钥失效、配额耗尽属于配置/外部服务问题，要与“无检索结果”区分；不得悄悄切换成 mock 结果。对同一依赖的连续失败，建议默认值：3 次失败后暂停自动重试 5 分钟，用户手动重试仍可触发探测。

## 六、平台集成能力

### 1. 接口设计与数据契约

页面调用统一的服务端 API；第三方密钥、Zotero 授权令牌和文件路径不返回浏览器。现有接口沿用仓库实现，新增能力按下表补充。所有异步创建接口返回任务 ID、初始状态和查询地址；成功接收任务建议返回 HTTP 202。

| 接口能力 | 状态 | 关键输入 | 关键输出/约束 |
| --- | --- | --- | --- |
| 创建检索并查看历史结果 | 现有 | 关键词、语种、年份、数量、排序；任务 ID | 检索任务与结果快照；历史任务按 ID 可重开，首页默认最近一次成功结果 |
| 创建精读并查询结果 | 现有 | DOI/链接/PDF、当前报告模板 | 持久化任务状态、原文、译文和报告的可下载文件 ID |
| 文献库导入与文件访问 | 现有 | 文献 ID、主题/文件 | 去重后的库条目；文件下载通过服务端对象 ID，不暴露物理路径 |
| `GET /api/search/{task_id}/analysis` | 本版新增 | 检索任务 ID | 各文献分析状态、可核对的摘要/目的/方法/实证过程与证据不足标记 |
| `POST /api/search/{task_id}/analysis/retry` | 本版新增 | 失败的结果 ID 列表、幂等键 | 仅重试失败项；返回分析任务 ID，不重复创建成功结果 |
| `GET /api/library/index-status`、`POST /api/library/{paper_id}/index/retry` | 本版新增 | 文献 ID | 切片/向量索引状态、失败原因、重建任务 ID；禁止用未完成索引回答 |
| 对话发送接口扩展 | 本版新增 | 会话 ID、问题、文献库检索模式 | 回复文本、引用文献 ID/片段位置、证据不足状态；原有会话历史继续保留 |

**接口规则：**请求、任务、文献、文件使用稳定 ID；创建与重试接口采用幂等键或业务唯一约束，避免重复入库/重复扣用量。列表分页、排序在服务端生效；文件接口校验对象状态后再读取。错误结构建议统一为 `{code, message, request_id, retryable}`，不包含密钥、数据库异常堆栈或本地绝对路径。接口文档需注明字段、状态码、示例和版本变更。

### 2. 跨模块业务规则

1. 检索结果与精读任务采用快照。外部元数据更新、模板替换或用户再次检索，不能改写已完成任务的历史展示。
2. 相同 DOI 优先合并；无 DOI 时使用规范化标题、年份、作者的组合去重。主题库关联保留，不能因再次导入产生重复主文献。
3. 精读任务创建时冻结模板版本；没有可读取模板则阻止新建并跳转设置。报告必须依据成功提取的原文生成，翻译、摘要压缩和报告各阶段有独立状态。
4. RAG 只从当前本地资料库中**索引成功且可追溯来源**的片段召回。删除文献后，相关切片同步失效；召回不足时明确告知，不编造引用。逐篇分析只写原文或摘要可证实的信息，缺全文时标注局限。
5. 检索、AI 分析、精读和 Zotero 导入各自记录结果与错误；一个阶段失败不能把其他已成功阶段改成失败，也不能把整条链路显示成完全成功。

### 3. 后台任务与状态恢复

| 任务 | 现状/本版方案 | 状态与调度 | 失败恢复 |
| --- | --- | --- | --- |
| 精读解析、翻译、报告 | 现有：FastAPI 后台任务 + MySQL 状态记录，启动时恢复遗留任务 | `queued → processing → completed/failed`；记录阶段、进度与产物 | 重启后根据持久化记录恢复；重复执行不得覆盖完整产物 |
| 检索结果逐篇 AI 分析 | 本版新增：持久化子任务 | 建议默认值：单进程并发 3 篇；每篇独立状态与重试计数 | 单篇失败可重试；刷新页面仍能看到已完成分析 |
| 文献入库后的切片与向量索引 | 本版新增：入库/文件更新触发后台任务 | 以文献版本和切片规则版本为索引键；记录排队、处理中、完成、失败 | 启动扫描未终结任务；重复执行覆盖同版本索引，不生成重片 |
| Zotero 附件导入 | 现有：用户主动触发 | 记录本地导入请求、来源与目标集合 | 客户端断开时不丢本产品产物；重新授权后可重试 |

本版仍是本机单进程服务。若改成多个 Web 工作进程，须先采用带租约的任务领取或独立队列，防止重复执行。任务进度和最终状态必须写入 MySQL，浏览器刷新或关闭后重新进入页面可恢复展示。建议默认值：任务状态轮询间隔 4 秒；高频进度写入按阶段或至少每 5 秒合并一次。

### 4. 消息通知与权限兜底

本版通知为站内反馈：任务创建后显示排队/处理中状态，完成、部分成功、失败时提供可点击的任务入口和重试动作；首页与任务记录读取相同的持久化状态。通知中心只展示本机任务，未实现邮件、短信或系统推送。重复状态更新不产生重复通知；任务结束后提示保留至用户处理或主动清除。

服务端逐接口校验输入、对象 ID、任务归属和文件状态，不能以“前端没有入口”作为权限控制。当前本地版没有登录机制，固定本机资料拥有者上下文仅在 `127.0.0.1` 绑定下成立；若尝试开启远程访问、共享链接或在线部署，必须先阻断数据接口，完成账号认证、会话管理、逐对象授权和跨用户隔离验收后才能开放。后台执行器只读取任务绑定对象，不接受浏览器指定任意文件路径。

## 七、非功能需求

以下指标是**本版验收目标（建议默认值）**，不是当前实测值。验收环境为本地 Windows 10/11、Chrome/Edge 近两个稳定版本、MySQL 正常运行；样本至少 1,000 篇库文献、单次 100 条检索结果、10 MB PDF。外部 API 可用性和模型生成时长单独记录，不纳入本地接口延迟统计。

### 1. 性能与容量

| 指标 | 验收目标 | 测量方式 |
| --- | --- | --- |
| 本地页面首屏 | P95 ≤ 2 秒 | 清缓存后进入首页/检索/文献库，各 30 次；不计第三方查询 |
| 文献库列表与任务列表 API | P95 ≤ 800 毫秒 | 1,000 篇文献、100 个任务，分页查询各 100 次 |
| 创建精读/分析任务 | P95 ≤ 2 秒返回任务 ID | 不等待模型完成；测 30 次接口响应 |
| 检索结果分页与筛选 | P95 ≤ 800 毫秒 | 100 条结果、每页 10 条，反复切页/筛选 100 次 |
| 后台状态可见延迟 | 完成或失败后 5 秒内可在页面看到 | 以任务持久化时间到页面更新的差值统计 |
| PDF 上传 | 单文件 ≤ 10 MB；上传失败不得生成空任务 | 边界值、错误格式与中断上传测试 |

外部检索或模型调用展示进度、超时和重试入口；不能用本地 API P95 指标掩盖 OpenAlex、SerpApi 或 DeepSeek 的耗时。并发分析上限和模型调用预算应可在服务端配置，避免一次检索触发无限并发。

### 2. 安全与隐私

- 服务默认仅监听 `127.0.0.1`；本地单用户模式不具备在线多用户权限保障。任何公网部署前必须补全身份认证和跨用户授权。
- `.env`、MySQL 密码、DeepSeek/SerpApi Key、Zotero 授权信息不得进入前端响应、版本库或普通日志；配置缺失时功能降级并给出配置提示。
- 上传仅接受声明的格式并核验文件内容、大小与 PDF 文件头；下载与外部 URL 请求限制 HTTPS、公网允许域名/地址规则，阻断内网地址、重定向绕过和任意本地文件读取。
- 对模型输入中的网页、PDF、文献文本按不可信资料处理。系统提示词要求引用原文、拒绝执行资料中要求泄露密钥或改变任务的指令；前端 Markdown 输出须消毒，防止脚本注入。
- 删除文献时同步删除或失效相关索引；保留日志不能包含原文全文、聊天正文、完整提示词、密钥或个人邮箱。用户应能在设置中看到外部数据流说明。

### 3. 稳定性、恢复与兼容性

- 数据库写入采用事务；任务创建、文献导入、索引重建和 Zotero 重试须幂等。异常或服务重启后以 MySQL 状态恢复，不出现“页面显示成功但没有产物”。
- 单一外部服务失败按第五章降级，检索结果、已下载文件和已完成分析继续可用。阅读任务的原文、译文、报告分别核验存在与可读取后才能标记完成。
- 建议默认值：提供每日一次本地数据库与文件备份指引/脚本，恢复目标 RPO ≤ 24 小时、RTO ≤ 2 小时；上线验收需实际完成一次备份还原演练。当前代码未提供自动备份时，不宣称已有该保障。
- 桌面版支持 Windows 10/11 和 Chrome/Edge 近两个稳定版本，适配 1366×768 及以上桌面视口；PDF 内嵌预览不可用时保留下载入口。中文标题、文件名和文献内容全链路使用 UTF-8，超长文件名经过安全截断而不丢失标题映射。

### 4. 日志与可观测性

| 观测对象 | 必须记录 | 不得记录 |
| --- | --- | --- |
| API 请求 | `request_id`、路由、状态码、耗时、错误码 | 密钥、令牌、完整请求正文、文件内容 |
| 外部调用 | 服务名、调用类型、耗时、重试次数、结果类别、配额/令牌用量（若可得） | 完整论文文本、用户问题原文、私密提示词 |
| 后台任务 | `task_id`、文献 ID、阶段、状态、失败原因分类、恢复次数 | 原文全文、译文全文、附件二进制 |
| RAG 与逐篇分析 | 索引版本、召回片段 ID、引用文献 ID、证据不足/失败标记 | 可识别个人资料的完整片段与对话正文 |

现有 `/api/health` 只反映部分本地配置状态，不能视为外部依赖探活。本版需增加数据库连接、任务积压、最近失败率和外部服务最近调用状态的诊断视图；外部服务探测应限频且不消耗大量配额。建议默认值：本地结构化日志保留 7 天，可按 `request_id → task_id → paper_id` 关联；连续 5 分钟任务失败率超过 20% 或积压超过 50 项时，在设置/任务记录给出显著告警和排查入口。
